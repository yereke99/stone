WEB APP / BACKEND GUIDE ДЛЯ ПРОЕКТА STONE
=========================================

Коротко:
Этот проект - Go backend для WhatsApp AI sales manager. Он принимает webhook от
Meta WhatsApp Cloud API, ведет диалог с клиентом по шагам, отвечает в WhatsApp и
продает AI рекламные ролики: Test, Basic, Standard.

Важно:
Это не frontend web-app с React/Vue. Здесь "web" часть - HTTP API:
- GET /health
- GET /webhook
- POST /webhook


1. ЧТО ДЕЛАЕТ ПРОЕКТ
--------------------

Проект автоматизирует первичный WhatsApp-диалог с клиентом.

Бизнес-логика:
- услуга: AI рекламные ролики за 48 часов без съемки;
- ролики готовы под запуск рекламы;
- цены:
  - Test format: 35 000 KZT
  - Basic format: 50 000 KZT
  - Standard format: 75 000 KZT
- языки: русский, казахский, английский;
- если язык непонятен, используется русский;
- каждое сообщение бота должно быть от 5 до 35 слов;
- бот использует только заданные ссылки на портфолио из конфигурации.

PORTFOLIO_STANDARD_URL=https://example.com/portfolio/standard-format

Обязательные переменные:
- APP_PORT
- ENV
- META_API_BASE_URL
- META_WEBHOOK_VERIFY_TOKEN

Необязательные, но нужные для реальной отправки WhatsApp сообщений:
- META_ACCESS_TOKEN
- META_PHONE_NUMBER_ID
- META_BUSINESS_ACCOUNT_ID
- META_APP_SECRET

Если META_ACCESS_TOKEN или META_PHONE_NUMBER_ID пустые, бот обработает webhook,
но Meta client вернет ErrNotConfigured и ответ не уйдет в WhatsApp.

Если META_APP_SECRET пустой, подпись webhook не проверяется.
Если META_APP_SECRET задан, POST /webhook требует корректный header:

X-Hub-Signature-256: sha256=<hmac_sha256_body>


5. HTTP ENDPOINTS
-----------------

GET /health
Возвращает состояние сервиса.

Пример ответа:

{
  "status": "ok",
  "env": "development",
  "started_at": "2026-05-11T08:00:00Z"
}


GET /webhook
Нужен для Meta webhook verification.

Meta отправляет query params:
- hub.mode
- hub.verify_token
- hub.challenge

Логика:
- если hub.mode == "subscribe"
- и hub.verify_token == META_WEBHOOK_VERIFY_TOKEN
- тогда сервис возвращает hub.challenge со статусом 200
- иначе 403

Пример:

curl "http://localhost:8080/webhook?hub.mode=subscribe&hub.verify_token=change-me&hub.challenge=123"

Ожидаемый ответ:

123


POST /webhook
Нужен для входящих WhatsApp events от Meta.

Логика:
1. Читает body максимум 1 MB.
2. Проверяет X-Hub-Signature-256, если задан META_APP_SECRET.
3. Парсит JSON в meta.WebhookPayload.
4. Достает только текстовые сообщения через payload.TextMessages().
5. Для каждого сообщения вызывает:

   h.bot.HandleIncoming(ctx, message.From, message.Text)

6. Для каждого reply вызывает:

   h.sender.SendTextMessage(ctx, message.From, reply.Text)

7. Возвращает JSON:

{
  "received": 1,
  "sent": 1,
  "failed": 0
}

Если Meta client не настроен, ответ не отправляется, но сервис не падает.


6. WEBHOOK PAYLOAD FLOW
-----------------------

Meta -> POST /webhook
  -> WebhookHandler.receiveWebhook
    -> VerifySignature
    -> json.Unmarshal
    -> payload.TextMessages()
    -> bot.Manager.HandleIncoming
      -> load user state
      -> detect language for new user
      -> calculate replies
      -> validate 5-35 words
      -> save state
    -> meta.Client.SendTextMessage
      -> POST {META_API_BASE_URL}/{META_PHONE_NUMBER_ID}/messages


7. BOT STATE MACHINE
--------------------

State хранится по userID, где userID = WhatsApp sender phone/id из message.From.

State:

type State struct {
    UserID       string
    Language     Language
    Step         Step
    UsedAIVideos *bool
    UpdatedAt    time.Time
}

Steps:
- welcome
- diagnostics_goal
- diagnostics_platform
- expertise
- offer
- portfolio
- closing

Порядок обычного диалога:

1. Новый пользователь
   - определяется язык
   - Step становится diagnostics_goal
   - отправляется welcomeMessage

2. StepDiagnosticsGoal
   - Step становится diagnostics_platform
   - отправляется askGoalMessage

3. StepDiagnosticsPlatform
   - Step становится expertise
   - отправляется askPlatformMessage

4. StepExpertise
   - Step становится offer
   - отправляется askUsedAIMessage

5. StepOffer
   - бот пытается понять, использовал ли клиент AI videos раньше
   - если да/нет понятно:
     - UsedAIVideos сохраняется
     - Step становится portfolio
     - отправляется offerMessage
   - если непонятно:
     - Step остается offer
     - отправляется clarifyUsedAIMessage

6. StepPortfolio
   - Step становится closing
   - отправляется portfolioPromptMessage

7. Любой другой/default
   - Step становится closing
   - отправляется questionnaireMessage


8. ГЛОБАЛЬНЫЕ ТРИГГЕРЫ БОТА
---------------------------

Перед обычным switch по step проверяются три группы фраз.

1. Objection:
   Слова:
   - дорого
   - подумаю
   - позже
   - expensive
   - think
   - қымбат
   - кейін

   Ответ:
   objectionMessage(language)

   Step не меняется.


2. Portfolio request:
   Слова:
   - портфолио
   - пример
   - кейс
   - portfolio
   - example
   - мысал

   Ответ:
   три сообщения:
   - Test format portfolio
   - Basic format portfolio
   - Standard format portfolio

   Step не меняется.


3. Ready signal:
   Слова:
   - готов
   - начнем
   - хочу
   - давайте
   - ready
   - start
   - дайын

   Действие:
   - Step становится closing
   - отправляется questionnaireMessage(language)


9. LANGUAGE DETECTION
---------------------

Файл:
internal/bot/language.go

Алгоритм:

1. Сначала ищет казахские маркеры:
   - ә, ғ, қ, ң, ө, ұ, ү, һ, і
   - сәлем, баға, қанша, қалай, қымбат, ойлан, сатылым

2. Если есть Cyrillic, возвращает ru.

3. Если есть Latin, возвращает en.

4. Если ничего не понятно, возвращает ru.

Примеры:
- "Здравствуйте, сколько стоит ролик?" -> ru
- "Сәлем, баға қанша?" -> kz
- "Hello, what is the price?" -> en
- "12345" -> ru


10. MESSAGE POLICY
------------------

Файл:
internal/bot/flow.go

Правило:
- каждое сообщение бота должно быть от 5 до 35 слов.

Константы:

const (
    minBotWords = 5
    maxBotWords = 35
)

Перед сохранением state и отправкой ответа вызывается:

validateMessagePolicy(replies)

Если сообщение нарушает лимит:
- HandleIncoming возвращает error;
- webhook handler логирует ошибку;
- reply не отправляется;
- state не сохраняется.

Важно:
wordCount не считает чисто числовые токены словами.
Например "35 000" не увеличивает count как обычные слова.


11. STORAGE
-----------

Сейчас используется:

internal/storage/memory.go

Плюсы:
- просто;
- быстро;
- удобно для локальной разработки.

Минусы:
- после рестарта все состояния пользователей пропадают;
- несколько инстансов приложения не делят состояние.

Чтобы заменить storage на PostgreSQL, Redis или другое хранилище, нужно
реализовать интерфейс:

type StateStore interface {
    Get(ctx context.Context, userID string) (State, bool, error)
    Save(ctx context.Context, state State) error
}

16. ШАБЛОН: НОВЫЙ HTTP HANDLER
------------------------------

Пример: добавить endpoint GET /version.

Создать файл:
internal/http/handler/version.go

Код:

package handler

import "net/http"

type VersionHandler struct {
    version string
}

func NewVersionHandler(version string) *VersionHandler {
    return &VersionHandler{
        version: version,
    }
}

func (h *VersionHandler) ServeHTTP(w http.ResponseWriter, _ *http.Request) {
    writeJSON(w, http.StatusOK, map[string]string{
        "version": h.version,
    })
}

Дальше изменить router:

func NewRouter(
    health *handler.HealthHandler,
    webhook *handler.WebhookHandler,
    version *handler.VersionHandler,
    logger *zap.Logger,
) http.Handler {
    mux := http.NewServeMux()
    mux.Handle("GET /health", health)
    mux.Handle("GET /webhook", webhook)
    mux.Handle("POST /webhook", webhook)
    mux.Handle("GET /version", version)

    return recoverMiddleware(logger, accessLogMiddleware(logger, mux))
}

Дальше изменить cmd/main.go:

versionHandler := httpHandler.NewVersionHandler("dev")

server := &http.Server{
    Addr: cfg.HTTPAddress(),
    Handler: httpserver.NewRouter(
        healthHandler,
        webhookHandler,
        versionHandler,
        zapLogger,
    ),
}


17. ШАБЛОН: НОВЫЙ JSON RESPONSE
-------------------------------

Используй общий helper:

writeJSON(w, http.StatusOK, map[string]any{
    "ok": true,
    "data": payload,
})

Для ошибок можно использовать стандартный http.Error:

http.Error(w, "invalid request", http.StatusBadRequest)

Стиль проекта:
- handlers маленькие;
- зависимости передаются через constructor;
- бизнес-логика не должна жить внутри router;
- JSON пишет writeJSON;
- logger передается явно.

22. ШАБЛОН: НОВЫЙ META MESSAGE METHOD
-------------------------------------

Сейчас есть только SendTextMessage.
Если нужен, например, image message, добавь новый метод в internal/meta/client.go.

Skeleton:

type SendImageRequest struct {
    MessagingProduct string `json:"messaging_product"`
    RecipientType    string `json:"recipient_type"`
    To               string `json:"to"`
    Type             string `json:"type"`
    Image            Image  `json:"image"`
}

type Image struct {
    Link string `json:"link"`
}

func (c *Client) SendImageMessage(ctx context.Context, to string, imageURL string) error {
    if c.cfg.APIBaseURL == "" || c.cfg.AccessToken == "" || c.cfg.PhoneNumberID == "" {
        return ErrNotConfigured
    }

    payload := SendImageRequest{
        MessagingProduct: "whatsapp",
        RecipientType:    "individual",
        To:               to,
        Type:             "image",
        Image: Image{
            Link: imageURL,
        },
    }

    requestBody, err := json.Marshal(payload)
    if err != nil {
        return fmt.Errorf("marshal meta image payload: %w", err)
    }

    url := fmt.Sprintf("%s/%s/messages", strings.TrimRight(c.cfg.APIBaseURL, "/"), c.cfg.PhoneNumberID)
    req, err := http.NewRequestWithContext(ctx, http.MethodPost, url, bytes.NewReader(requestBody))
    if err != nil {
        return fmt.Errorf("create meta image request: %w", err)
    }

    req.Header.Set("Authorization", "Bearer "+c.cfg.AccessToken)
    req.Header.Set("Content-Type", "application/json")

    resp, err := c.httpClient.Do(req)
    if err != nil {
        return fmt.Errorf("send meta image message: %w", err)
    }
    defer func() {
        _ = resp.Body.Close()
    }()

    if resp.StatusCode < http.StatusOK || resp.StatusCode >= http.StatusMultipleChoices {
        responseBody, _ := io.ReadAll(io.LimitReader(resp.Body, 4096))
        return fmt.Errorf("meta api returned status %d: %s", resp.StatusCode, strings.TrimSpace(string(responseBody)))
    }

    c.logger.Info("meta image message sent", zap.String("to", to), zap.Int("status", resp.StatusCode))
    return nil
}

Если этот метод нужен handler-у, расширь interface MessageSender.

    "context"
    "testing"

    "github.com/yereke99/stone/internal/storage"
    "go.uber.org/zap"
)

func TestManagerFlow(t *testing.T) {
    manager := NewManager(
        storage.NewMemoryStore(),
        PortfolioLinks{},
        zap.NewNop(),
    )

    replies, err := manager.HandleIncoming(context.Background(), "user-1", "Здравствуйте")
    if err != nil {
        t.Fatal(err)
    }
    if len(replies) != 1 {
        t.Fatalf("expected 1 reply, got %d", len(replies))
    }

    replies, err = manager.HandleIncoming(context.Background(), "user-1", "Хочу заявки")
    if err != nil {
        t.Fatal(err)
    }
    if len(replies) != 1 {
        t.Fatalf("expected 1 reply, got %d", len(replies))
    }
}

25. ШАБЛОН: MOCK MESSAGE SENDER ДЛЯ WEBHOOK TEST
------------------------------------------------

WebhookHandler зависит от interface:

type MessageSender interface {
    SendTextMessage(ctx context.Context, to string, body string) error
}

Для тестов можно сделать fake sender:

type fakeSender struct {
    sent []string
}

func (f *fakeSender) SendTextMessage(ctx context.Context, to string, body string) error {
    if err := ctx.Err(); err != nil {
        return err
    }
    f.sent = append(f.sent, body)
    return nil
}

Так можно тестировать webhook без реального Meta API.

28. CODE STYLE В ЭТОМ ПРОЕКТЕ
-----------------------------

Следуй такому стилю:

- Go стандартный net/http, без внешнего router framework.
- Handlers реализуют ServeHTTP.
- Зависимости передаются через constructor.
- Логи через zap.Logger.
- Ошибки оборачиваются через fmt.Errorf("context: %w", err).
- Конфиг читается из env.
- Бизнес-логика бота живет в internal/bot.
- HTTP слой не должен знать детали state machine.
- Meta API детали живут в internal/meta.
- Storage заменяется через interface bot.StateStore.
- Тексты бота держатся в flow.go.
- Каждый новый текст должен проходить 5-35 word policy.
- После изменения логики запускать go test ./...

31. БЫСТРЫЙ MENTAL MODEL
------------------------

Думай о проекте так:

HTTP layer:
  принимает запросы, проверяет webhook, отдает JSON.

Meta layer:
  знает формат WhatsApp Cloud API.

Bot layer:
  решает, что ответить клиенту.

Storage layer:
  помнит, на каком шаге находится клиент.

Config layer:
  берет настройки из env.

Main:
  склеивает все части вместе и запускает сервер.

35. КЛЮЧЕВОЙ ПРИНЦИП ПРОЕКТА
----------------------------

Проект держится на простом разделении:

WebhookHandler не должен становиться большим "комбайном".
Он только принимает webhook, достает text messages, вызывает bot manager и
отправляет replies через sender.

Bot Manager не должен знать детали Meta API.
Он получает userID + text и возвращает []Reply.

Meta Client не должен знать бизнес-логику.
Он только отправляет payload в WhatsApp Cloud API.

Storage не должен знать про HTTP или Meta.
Он только сохраняет и достает bot.State.

Если соблюдать это разделение, проект легко расширять.
